20 ноября 2026 (UTC). Основа — неизменённый архив 1.2.0. Все прежние compiler-evidence JSON сохранены побайтно. Проверены все 23 исходных OPEN-вопроса; [поимённый результат и необходимые материалы](RESIDUE_23_130.md).

## Объём и метод

**315 новых наблюдений сборки**, из них 126 Win32, 127 Win64, 31 ARM32 и 31 ARM64. 179 Windows-запусков: 175 с exit=0 и **4 сохранённых неуспешных запуска** DLL consumer. Получены 30 ELF-библиотек без выполнения и 8 C++-заголовков. Шесть дополнительных наблюдений IDE-debugger не считаются шестью новыми компиляциями.

Каждый fixture имеет отдельный каталог, закреплённые DPR/DPROJ/PAS/INC/RES, хэши и событие завершения именно своего проекта. Использовалось штатное действие IDE Build через MCP2Delphi. Прямые CLI-ограничения Community Edition не обходились. Вывод и диагностики сохранены отдельно от исходного ожидания; OBSERVATION_ONLY не означает нормативный PASS. ARM не развёртывался и не запускался. Заголовок HPP не является проверкой внешнего C++ ABI.

IDE трижды завершалась во время ранних ARM-попыток. Эти попытки и restart receipts сохранены в частном рабочем аудите. Сбой IDE не засчитан как отказ языка. Две linker-попытки с потерянным относительным working directory оставлены с E2597/F2588; те же source bytes собраны в свежих controls с абсолютными output paths. Два готовых ELF найдены в SDK working directory и привязаны к завершившемуся вызову по имени, времени, исходникам и хэшу. В публичном DPROJ этих двух controls пути вывода закреплены, как при проверке; при локальном повторе их нужно направить в свой каталог.

В одной сессии панель IDE возвращала обычный MSBuild-log вместо native строки Building. Сохранён настоящий вывод; профиль проверяется по имени проекта, target compiler и define DEBUG/RELEASE. Синтетическая строка Building не добавлялась.

## Содержательные исправления

- `record` и `unmanaged`: 80 compile observations на четырёх targets; plain array/pointer — важные контрпримеры отношению «подмножество». ARM здесь проверяет принятие и ELF, не действие runtime.
- Resource predicates — список условных identifiers; `OR` сам может быть identifier. Прежняя формулировка про булев OR исправлена.
- Три табличных IFOPT-имени исправлены и проверены независимо. Числовое IFOPT не приравнивается к конечным битам PE.
- Сопоставление NOINCLUDE проверено по новым ConsumerU.hpp, а не по одному отсутствию ошибок DCC.
- D1/D2 проверены потребителем-debugger: breakpoint, Input=41, step, LocalValue=42. D0 не попал на запрошенную строку. Промежуточный line=0 одного API сохранён вместе с фактическим thread line=10 при evaluation.
- Windows DLL: прежний global-frame consumer печатал TRUE, затем падал при завершении после FreeLibrary. Scoped consumer завершает managed работу в процедуре до unload и проходит с тем же producer. Точная внутренняя причина не присочинена.
